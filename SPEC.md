# Interface spec

Frozen contracts. Every component builds against this file. Change it here first,
not in an implementation.

## Concept

A high-capability model authors a **runbook** once. A small local model executes
that runbook repeatedly, on the machine the documents are already on. The runbook
fixes the control flow, the schemas, and the checks. The local model supplies the
per-document judgment.

Reasoning that happens **once** lives in the runbook. Reasoning that happens
**every run** happens locally.

`src/probe.py` records whether a public host was reachable during a run. It is
diagnostics recorded into the run file, not a claim the pipeline makes. The
substantive privacy property is that every model call goes to loopback, so no
document is transmitted anywhere regardless of what the network was doing.

## Layout

```
runbooks/          triage-inbox.json, triage-contracts.json, redact.json
corpus/inbox/      ~25 .eml
corpus/contracts/  ~20 .txt
corpus/PLANTED.json    ground truth for the survival scan. NEVER shown to a model.
src/               run.py, loaders.py, model.py, checks.py, report.py, probe.py
out/               run-<timestamp>.json + report.html   (gitignored)
tools/             make_corpus.py, baseline_regex.py
```

## Runbook schema

```json
{
  "id": "triage-inbox",
  "version": "1.0",
  "authored_by": "frontier model, once, offline thereafter",
  "authored_on": "2026-08-23",
  "purpose": "One sentence, readable aloud from a projector.",
  "input":  { "glob": "corpus/inbox/*.eml", "loader": "eml" },
  "steps": [
    { "n": 1, "name": "Read 25 emails from disk",                 "op": "load"    },
    { "n": 2, "name": "Classify and extract from each email",     "op": "extract" },
    { "n": 3, "name": "Validate every record",                    "op": "check"   },
    { "n": 4, "name": "Assemble the routing report",              "op": "report"  }
  ],
  "extract": {
    "prompt": "...{document}...",
    "schema": { "...flat JSON Schema..." },
    "options": { "temperature": 0, "seed": 7, "num_ctx": 8192 }
  },
  "checks": [ { "id": "...", "kind": "...", "..." } ],
  "report": { "group_by": "category", "highlight": "urgency" }
}
```

Rules:
- `steps[].name` is projector copy. Plain language, no function names.
- `op` is one of `load`, `extract`, `check`, `report`, `redact`.
- `extract.schema` must stay **flat**: object of scalars, no nesting, no `$ref`.
  JSONSchemaBench shows small models collapse on deep schemas.
- `extract.prompt` contains the literal token `{document}`.

## Extraction schemas

**Inbox** (6 flat fields):

| field | type | values |
|---|---|---|
| `category` | enum | `customer_complaint` `invoice_dispute` `sales_inquiry` `job_application` `vendor_quote` `internal_hr` `support_request` `spam` |
| `urgency` | enum | `today` `this_week` `no_deadline` |
| `summary` | string | one line |
| `action` | string | one line, imperative |
| `owner` | enum | `support` `finance` `sales` `people_ops` `none` |
| `contains_personal_data` | boolean | |

**Contracts** (7 flat fields):

| field | type | values |
|---|---|---|
| `doc_type` | enum | `service_agreement` `nda` `lease` `saas_subscription` `statement_of_work` `maintenance` |
| `counterparty` | string | |
| `renewal_basis` | enum | `fixed_date` `anniversary_of_execution` `auto_renew_unless_notice` `fiscal_year_end` `none` |
| `renewal_date` | string | ISO `YYYY-MM-DD` or `unknown` |
| `notice_days` | integer | `0` when not applicable |
| `expires_within_90_days` | boolean | |
| `contains_personal_data` | boolean | |

`renewal_basis` is the field that defeats a regex baseline. A pattern match can
find a date; it cannot tell that "renews on the anniversary of execution" means
the date must be computed from a different field.

**Redaction** (per document):

| field | type | values |
|---|---|---|
| `redacted_text` | string | full text with each identifier replaced by `[KIND]` |
| `removals` | array | flat objects: `{ "text": str, "kind": enum }` |

`kind` enum: `person_name` `street_address` `phone` `email` `account_id`
`medical_detail` `employment_detail` `deal_term`

This is the one place a nested value is allowed, because `removals` is a list of
two-scalar objects. Keep it at that depth.

## corpus/PLANTED.json

Ground truth for the survival scan. Generated by `tools/make_corpus.py`.
Never included in any prompt.

```json
{
  "generated_on": "2026-08-23",
  "identifiers": [
    { "id": "P01", "file": "inbox/012-hr-escalation.eml",
      "text": "Marcus Whitfield", "kind": "person_name" }
  ]
}
```

## Checks

Printed as explicit `PASS` / `FAIL` lines. They are demo content, not plumbing.

| id | kind | asserts |
|---|---|---|
| `parses` | structural | model output parses as JSON |
| `record_count` | structural | one record per input file |
| `file_mapping` | structural | every record maps to a real input file |
| `enum_valid` | structural | every enum field holds an allowed value |
| `required_present` | structural | every required field present and non-empty |
| `date_format` | semantic | `renewal_date` is ISO or exactly `unknown` |
| `survival_scan` | semantic | **no `PLANTED.json` identifier string appears in any `redacted_text`** |

Failure handling: retry the call once, then mark the record `needs_review` and
continue. **The run never crashes.** A record failing twice is the exceptional
case that would escalate to a more capable model, which is on-message.

## out/run-<timestamp>.json

```json
{
  "run_id": "2026-08-23T19-52-11",
  "device":  { "label": "MacBook Pro M4 Pro", "os": "darwin", "ram_gb": 48 },
  "model":   { "name": "gemma4:12b", "digest": "4eb23ef187e2" },
  "network": { "probe": "unreachable", "detail": "getaddrinfo failed", "at": "..." },
  "local":    { "calls": 45, "prompt_tokens": 0, "output_tokens": 0, "wall_seconds": 0.0 },
  "frontier": { "calls": 3,  "prompt_tokens": 0, "output_tokens": 0,
                "when": "runbook authoring, 2026-08-23", "model": "..." },
  "checks":  { "passed": 0, "failed": 0, "details": [] },
  "records": [],
  "removals_total": 0
}
```

Local token counts come from Ollama's own response fields, `prompt_eval_count`
and `eval_count`. They are measured, not estimated.

## Comparative panel: the honesty rule

The report shows frontier work beside local work. **Tokens are not fungible
across models.** A frontier token doing architectural design is not equivalent to
a local token doing field extraction.

The claim is **amortization, not equivalence**: the expensive capability was
needed once, the volume was handled locally. Any per-run cost figure must carry
the rate and the date it was quoted.

Do not render a line that reads "local did N times the work."

## Cross-platform

Targets macOS (M4 Pro, 48 GB unified) and Windows (RTX 5080, 16 GB VRAM).

- Python 3.11+ stdlib plus `requests`. No `mlx`, no platform-specific shell-outs.
- `pathlib` for every path.
- The network probe is a socket call, not `networksetup`.
- `--device-label` records which machine produced a run, so two runs can sit
  side by side in the report.

## Model targets

Two models carry the demo. Verified against the Ollama registry 2026-08-23.

| tag | lab | size | context | role |
|---|---|---|---|---|
| `gemma4:12b` | Google | 7.6 GB | 256K | primary. Headline numbers are quoted from this |
| `qwen3.8:27b` | Alibaba | 18 GB | 256K | newest generation, Aug 2026. The ceiling |

`qwen3.5:4b` (3.4 GB) and `qwen3.5:9b` (6.6 GB) are also pulled and stay in the
bake-off as the small end of the curve, which is what makes "how good is good
enough" a measured question instead of an assertion.

Reproducibility: `gemma4:12b` fits a 16 GB consumer GPU, which is why the
headline results are quoted from it. `qwen3.8:27b` at q4 is 18 GB and will not
fit 16 GB of VRAM; a smaller quantization is the route on a 16 GB card, and the
Qwen3.8 tag list runs from IQ2_XXS (9 GB) upward.

Also available and deliberately not used:

- **`muse-glimmer:30b`** (Meta, 18 GB, Apache 2.0) is Meta's current open model,
  described as built for "always-on local agents, tuned for tool use, long tasks,
  and failure recovery". That is this repo's exact workload, so it is the most
  interesting untested model for this task. One command to add.
  Note `llama4` is a year stale and only ships `16x17b` / `128x17b` MoE.
- **MLX-tagged variants** are faster on Apple silicon and do not run on an NVIDIA
  card. A result that reproduces on one vendor's hardware only is not the claim
  this repo makes.

**Thinking models.** The qwen3.x family and Qwen3.8 default to reasoning mode,
and Qwen3.8 additionally supports `reasoning_effort`. In that mode Ollama returns
generated JSON in `thinking` and leaves `response` empty. `src/model.py` sends
`"think": false` for extraction and falls back to `thinking` regardless. This cost
a full bake-off round before it was diagnosed; see the finding in README.md.

## Ollama call contract

- `POST http://127.0.0.1:11434/api/generate`
- `format` carries the **full JSON Schema object**, at the top level of the body,
  not inside `options`. Verified against current docs 2026-08-23.
- `stream: false`
- `keep_alive: -1` so the model never unloads mid-session. Default is 5 minutes.
- Warm up before timing anything: post `{"model": ..., "keep_alive": -1}` with no
  prompt.
- `format` constrains output, it does **not** validate it. The checks above are
  required, and Ollama's own docs say so.
